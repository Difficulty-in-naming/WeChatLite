# 源码与发布检查

每次推送提交都会自动运行 Windows x64 和 macOS arm64 的 Actions 构建，也保留手动触发入口。测试通过后，程序包和校验文件作为对应运行的 Artifacts 保存七天；测试诊断单独保存，不进入程序包。自动提交构建不创建或覆盖正式 Release。

此仓库初次上传前采用明确的源码目录清单，排除系统应用数据、`.state`、`.research`、`artifacts`、构建目录、工具、运行缓存和旧发布文件。未将整个工作区直接提交。

检查包括 Gitleaks 8.30.1 默认规则扫描，以及将候选文件与本机真实管理员密钥、客户端接入密钥、云入口接入凭据和服务端 TLS 私钥做精确比对。报告不输出密钥原文，私有检查结果不进入仓库或 Release。

TLS 离线测试源码中的固定私钥为公开的合成测试身份，只供临时 loopback fixture 使用，从不认证真实服务；在对应声明处显式标记 `gitleaks:allow`。这几处不是运行凭据，不应复制到实际配置。

发布目录仅从全新暂存目录构建，检查允许的文件和目录，禁止测试程序、Qt Test、日志、截图、调试产物、私钥、数据库和本机配置。程序依赖、使用说明及第三方许可证/源码材料仍保留。

Windows 每个角色产生一个便携 EXE。首次运行到当前用户的持久版本化缓存释放并校验程序依赖；后续复用。运行数据独立保存。客户端与服务端各自运行，不因拆包重新生成客户端密钥或改变授权群。

Mac 每份 DMG 只包含一个自包含 `.app`，运行库、helper、使用说明和许可证放在包内。构建后进行依赖路径、架构、包内容和签名校验。签名身份由 `CODESIGN_IDENTITY` 决定：未设置时自动使用本机检测到的 Apple Development 证书，检测不到则回退 ad-hoc。发布用的 Developer ID 签名及 Apple 公证尚未完成。

Mac 服务端当前没有本机微信适配器，此限制同时出现在使用说明与 Release 说明中。Mac 客户端连接 Windows 微信服务端是当前支持的使用方式。

扫描工具无法证明任何代码绝对不含敏感信息；添加新的配置、日志、fixture 或二进制时仍需重新审查，禁止通过关闭扫描器绕过真实凭据告警。
