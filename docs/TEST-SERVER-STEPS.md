# 测试版服务端：完整操作步骤

目标：跑一份带**引用定位修复**的适配器，拿到控制台诊断输出，同时不影响你现在用的正式便携包。

**需要停掉原来的服务端。** 原因在第 1 步。

---

## 第 1 步：停掉原来的服务端

**为什么必须停**——三个硬冲突：

1. **端口冲突**：测试版复制你的配置，用同一个 `10.211.55.8:8765`。原来的还在跑，新的启动就会报「无法监听配置的服务地址」。
2. **数据目录锁**：`data\.relay.lock` 是排他锁，两个进程指向同一份数据时第二个抢不到。
3. **适配器抢微信库**：两个 `wechat-adapter.exe` 同时读微信数据库会互相干扰，读到的可能是残缺快照——**你现在的"收不到消息"可能就是这造成的**。

**怎么停**：

1. Windows 托盘 → 微信轻聊服务端图标 → 右键
2. 选 **「停止服务并退出」**

不要只关窗口，那只是收起到托盘。

**确认停干净**：任务管理器（Ctrl+Shift+Esc）→ 详细信息 → 搜 `wechat-relay` 和 `wechat-adapter`，两个都不应该出现。

---

## 第 2 步：备份配置（可选但建议）

配置默认在这里：

```
%LOCALAPPDATA%\WeChatLite\WeChatLiteServer\server.json
```

要确认准确路径：打开原来的服务端管理窗口 → **「服务状态」页** → 看「配置」那一行。

把这个 `server.json` 复制到桌面，顺便看一眼里面的 `data` 字段指向哪个目录，那个目录也备份一份（如果里面有你在意的东西）。

> 如果你不打算保留测试期间的消息，可以跳过备份——原目录不会被测试版改动。

---

## 第 3 步：打开测试目录

共享目录里已经准备好，**不用解压**：

```
\\Mac\Home\Downloads\WeChatLite-构建产物\WeChatLite-Server-测试版\
```

双击 `wechat-server.exe`。

如果你想让它用**同一份配置**（推荐的验证方式），就用命令行指定配置路径。

---

## 第 4 步：启动（两种方式，选一种）

### 方式 A：用原配置（推荐）

这样连接参数、密钥、选中的群全部一致，客户端不用改任何东西。

1. 在测试目录里，按住 `Shift` + 右键空白处
2. 选「在此处打开 PowerShell 窗口」或「在终端中打开」
3. 粘贴执行（把路径替换成第 2 步看到的真实路径）：

```powershell
.\wechat-server.exe --config "$env:LOCALAPPDATA\WeChatLite\WeChatLiteServer\server.json"
```

> 路径两边**必须**有引号，里面有空格。

### 方式 B：用独立配置（完全隔离）

不碰原配置，但需要重新填密钥、重新选群。

1. 直接双击 `wechat-server.exe`
2. 它会创建 `%LOCALAPPDATA%\WeChatLite\WeChatLiteServer\server.json`
   - 如果这个文件已经存在（你原来的配置），它会直接用你原来的——所以想完全隔离得先改名那个文件

**建议用方式 A。** 验证适配器行为不需要隔离配置。

---

## 第 5 步：确认起来了

启动后应该看到：

1. **一个黑色控制台窗口**（正式便携包没有这个，因为它是 GUI 子系统程序）
   —— **这是关键，别关它**
2. 管理窗口打开，「服务状态」页
3. 点 **「启动服务」**（如果是 `--start` 参数启动的会自动开始）
4. 状态变成绿色「运行中」

控制台窗口里应该开始出现类似：

```
[timing] poll kind=text rows=... snapshot=...ms match=...ms waited=...ms
```

---

## 第 6 步：测新消息能不能收到

**这一步是核心。**

1. 手机微信给测试群（`56266522281@chatroom`「测试群」）发一条**文字**：`测试1`
2. 等 10 秒
3. 看客户端里有没有出现

同时盯控制台。

### 三种结果

**A. 控制台持续打印 `[timing] poll`，但客户端收不到**

→ 证实推断：适配器读到签名变化，但用旧快照查不到新行。

**把控制台最后 20 行贴给我。**

**B. 控制台没输出 / 启动后就停了**

→ 卡在更早的环节（读微信库、读密钥、进程通信）。

**把从启动开始的全部输出贴给我。**

**C. 消息正常收到了**

→ 之前的"收不到"和适配器版本无关，是偶发的。需要进一步看是不是特定类型（图片/引用）才触发。

---

## 第 7 步：测引用定位

新消息收发正常后再做。

1. 群里找一条**引用消息**
2. 点引用块 → **「定位到原文位置」**

### 结果对照

| 看到什么 | 含义 |
|---|---|
| 「已定位到原文」并跳过去 | 成功 |
| 「已定位到原文（按发送者和内容匹配）」 | 客户端本地匹配成功 |
| 「已加载的消息里没有找到这条引用的原文」 | 本地没有，需要翻历史 |
| 「…（no stored row has server_id N）」 | 微信库里没这个编号 |
| 「…（not unique in this group）」 | 同编号多行，拒绝猜 |
| 「…（was recalled）」 | 原消息已撤回 |
| **「原消息尚未同步或不可用」** | **跑的还是旧适配器** |

最后一条最关键——那句旧文案在新版里已经不存在了。看到它就说明第 3 步的文件不对。

---

## 第 8 步：有问题怎么办

### 「无法监听配置的服务地址」

原服务端没停干净。回第 1 步，用任务管理器确认进程消失。

### 「此配置的服务端管理窗口已经在运行」

原管理窗口还开着（`QLockFile` 拦住）。从托盘图标打开原来那个，正常退出。

### 「微信新分片密钥尚不可用」

适配器读不到微信数据库密钥。通常等 30 秒就好，或者重启一次测试服务端。也可能是微信没登录。

### 图片一直「微信附件暂未就绪」

检查 `adapter\ffmpeg.exe` 在不在（约 87 MB）。被杀毒隔离的话 WXGF 图片永远解不出来。

---

## 第 9 步：测完怎么恢复

1. 停掉测试服务端（托盘 → 停止服务并退出）
2. 双击 `\\Mac\Home\Downloads\WeChatLite-构建产物\WeChatLite-Server-Windows-x64-patched.exe`

它会复用原来的缓存和配置，和你测试前一模一样。

**测试目录随便删**，不影响任何东西。

> 注意：测试期间的收发记录写在 `server.json` 的 `data` 指向的目录里。如果你用方式 A（共享配置），测试期间的消息会**进入你原来的数据目录**。这是好事——测完切回去消息还在。
