# 微信轻聊

轻量的 C++ / Qt Widgets 聊天客户端，配合独立的 Qt 管理界面、Rust 转发核心和本机微信适配器。客户端可以运行在另一台电脑，服务端只访问其本机已登录的微信。

## 下载与运行

在 [Releases](https://github.com/Difficulty-in-naming/WeChatLite/releases) 下载对应平台、对应角色的程序。客户端和服务端分开运行、分开分发。

| 平台 | 客户端 | 转发服务端 |
| --- | --- | --- |
| Windows x64 | `WeChatLite-Client-Windows-x64.exe` | `WeChatLite-Server-Windows-x64.exe` |
| Apple Silicon Mac | `WeChatLite-Client-macOS-arm64.dmg`，内含“微信轻聊.app” | `WeChatLite-Server-macOS-arm64.dmg`，内含“微信轻聊服务端.app” |

Windows 每个角色只需分发一个 EXE。首次启动会校验并释放依赖到当前用户的版本化应用缓存；后续复用，启动器在打开实际应用后退出。它是单文件分发，并非把 Qt、Rust helper、微信适配器全部静态链接成一个进程。用户配置、聊天数据与下载目录独立于程序缓存。

服务端“设置 → 开机自启”可选择登录系统后自动启动本应用和转发服务，默认关闭；Windows 和 Mac 分别使用当前用户的系统启动项，更新后会跟随新程序路径。

Mac 使用自包含的 `.app`，在 Finder 中是一个应用，依赖和使用说明位于应用内部。DMG 是下载载体。当前构建采用 ad-hoc 签名，尚未完成 Developer ID 签名与 Apple 公证。

**当前 Mac 本机微信适配器尚未实现。Mac 客户端可以连接 Windows 微信服务端；Mac 服务端包仅包含管理 GUI、Rust 核心与 P2P 模块，不能直接转发本机 Mac 微信。** Windows 适配器限定微信 **4.1.15.13**，版本或指纹不匹配会拒绝接入。

## 首次连接

1. 在微信所在的 Windows 电脑运行服务端，配置连接、存储和 TLS，启动服务。
2. 在“转发群”勾选需要转发的群。新发现的群默认不转发。
3. 在“客户端权限”新建客户端，指定允许的群、发送/撤回与下载权限。
4. 将连接信息交给该客户端，在客户端设置中粘贴并保存。以后可选中该客户端，点击“复制连接信息”再次取得；重启服务后仍可复制或显示密钥。

实际可见群是全局转发范围与该客户端授权范围的交集。管理员密钥只允许真实本机回环连接，不能发给客户端；停用或撤销客户端会中断其事件连接，并立即限制历史、成员、发送、上传及下载。

可选择 HTTPS 直接地址，或自建公网入口的自动连接。自动连接使用固定设备身份，QUIC 直连优先，无法直连时加密中继；微信电脑不必映射路由器端口。原 HTTPS/WSS、独立客户端密钥与证书指纹校验保留。入口只负责建联与必要的中继，不保存聊天数据库。

详细步骤：[客户端](docs/CLIENT.md)、[服务端](docs/SERVER.md)、[P2P 连接](docs/P2P.md)、[公网入口部署](deploy/p2p/README.md)。

## 聊天功能

- 拖拽或粘贴文件、图片、视频与 GIF，先附加到输入区，再发送；单件上限 512 MiB，每次最多 12 个附件。
- 接收文件、视频、GIF 和语音。下载保存到自选目录的 `YYYY-MM-DD` 子目录；图片、GIF、视频和文件交给系统默认应用打开，语音在聊天窗口内播放。
- 输入 @ 选择真实成员；右键头像可 @。右键文本可复制、引用，以及在本人已确认的纯文本消息发送不足三分钟时请求撤回。撤回后可重新编辑本客户端保留的原稿；引用可定位原文。
- 列表平滑滚动，向上按需读取更早消息，并保持阅读位置；内存消息窗口最多 300 条。
- 窗口按可用屏幕与缩放调整，输入框上沿可上下拖动并保存高度，无附件时可缩到约 100 个逻辑像素。气泡文字支持拖选，复制选中的部分。
- 右上角“聊天记录”打开独立窗口，支持关键词、文件/图片与视频/链接/语音、日期与群成员筛选，点击结果定位原文；每页最多 50 条、窗口最多保留 200 条。“群公告”按需读取服务端本机微信中的公告，显示发布人、时间和只读正文，区分未设置与暂不可读。
- 右键群可置顶/取消置顶，并从“忽略通知 / 仅被 @ 时通知 / 所有新消息通知”中选择一档，默认全部通知，重启后保留。仅被 @ 时按真实微信成员身份匹配，也接收 @所有人。允许的他人新消息使用系统原生通知，当前正在浏览的群也适用；历史加载、断线重放、重复事件、状态更新和自己发送不弹通知。系统权限和勿扰设置仍由操作系统控制。
- 不显示无意义的操作提示条或鼠标悬停提示；聊天区域不加入通话、表情工具栏等额外按钮。
- 搜索框左侧设置按钮可修改下载位置、查看用量和清理自动预览/语音缓存，并选择缓存上限。提供跟随系统、浅色、深色主题，以及新消息提示音开关与试听。
- 客户端“设置 → 更新”、服务端“设置 → 检查更新”可查询 GitHub 正式 Release；新版本按系统和角色自动下载，流式写入并校验 SHA-256。支持取消、重试与下载进度，关闭设置后继续下载。完成后退出对应应用再替换原程序，用户数据独立保留。
- 视频卡片按可见范围读取小封面，聊天与聊天记录共用缓存；预览不下载整段视频。媒体刚开始等待时快速检查就绪状态，长期未就绪才逐步退避；完整视频缓存优先命中，避免额外目录扫描。
- 常见微信方括号表情会显示为对应表情，未知别名保留；原始文本、复制、引用和微信发送数据不变。

发送提交与微信确认分别记录；不确定结果不会自动重发。稳定请求编号用于去重。原生文本引用只接受本机数据库中已确认的同群文本。撤回通过原版微信的菜单提交，只以同一消息的数据库撤回记录确认成功；未经文档化的原生撤回队列已停用。

只有用户主动请求撤回时才可能将服务端电脑的原版微信切到目标群并置于前台，这可能把该群标为已读。普通转发、重连、选取转发群和结果轮询不操作原版微信界面。群名、账号、相邻文本或菜单无法精确校验时拒绝提交；无法确定是否已提交的结果不会自动重试。

## 资源与数据

界面只绘制可见消息，图片、GIF 和缩略图缓存有上限；最小化或隐藏后释放动画资源。附件流式写入磁盘。Rust 转发、P2P 与微信桥接使用有界队列和缓冲，没有 Python、Electron 或浏览器运行时。

Windows 转发核心与适配器以无控制台的独立进程启动，保留管道日志和优雅退出，省去两个额外的控制台宿主。内存报告区分总驻留内存（包含可共享系统页）与专用内存；当前完整界面不承诺总驻留稳定低于 50 MB。

Windows 桥接的数据库读取、媒体处理和发送确认使用 Rust，SILK 解码链接 C SDK，原生发送与引用使用经版本校验的 C++ 组件，撤回使用适配器内静态链接的 C++ UI Automation 辅助代码，WXGF 按需调用独立 FFmpeg。客户端不包含本机微信适配器。

源码与发布包不携带真实接入密钥、服务器设备私钥、SSH 凭据、聊天数据库或个人附件。运行配置保存在各自系统应用数据目录。发布前审查说明见 [源码与发布检查](docs/RELEASE.md)。

## 从源码构建

Windows：Qt 6.8.3（Widgets、Network、WebSockets、Svg、Test）、CMake、MSVC x64 / Windows SDK 与 Rust MSVC 工具链。准备带 HEVC 解码、PNG 输出及测试所需 libx265 编码器的独立 FFmpeg EXE。

```powershell
powershell -File scripts/build-windows.ps1 -QtRoot C:\Qt\6.8.3\msvc2022_64 -FFmpeg C:\Tools\ffmpeg.exe
```

脚本构建和测试原生模块、Rust 核心/桥接/P2P、Qt 客户端与管理端，再创建干净运行目录及便携单 EXE。开发工具默认复用工作区 `.qt`、`.tools`，不属于运行包。

Apple Silicon Mac：Xcode Command Line Tools、Qt 6.8.3+、CMake、Rust。当前构建最低系统版本 macOS 13。

```bash
QT_PREFIX=/path/to/Qt/6.8.3/macos bash scripts/build-macos.sh
```

每次向 GitHub 推送提交，Actions 都会自动运行 `Windows x64 packages` 和 `macOS arm64 packages`，也可分别手动运行。Windows 使用显式的 `windows-2025-vs2026` runner、VS 2026 和 CMake 4.4.4，Mac 使用原生 arm64 runner；两端固定 Qt 6.8.3 和 Rust 1.95.0，先通过离线测试、依赖部署和包内容校验，再生成客户端与服务端。

在仓库 **Actions → 对应工作流 → 对应提交的成功运行 → Artifacts** 下载 `Windows-x64-packages` 或 `macOS-arm64-packages`。前者只含两个便携 EXE 和校验值，后者只含两个 DMG 和校验值；默认保留七天。测试诊断另存，不进入程序包。提交构建不会自动创建或覆盖正式 Release，正式版本仍在 Releases 下载。

```text
cargo test --locked -p wechat-relay -p wechat-adapter -p wechat-p2p
ctest --test-dir build -C Release --output-on-failure
ctest --test-dir build/native -C Release --output-on-failure
```

默认自动化使用演示服务、离线样本或合成 fixture，不发送真实微信群消息。真实 WeChat 适配器、系统通知视觉效果、不同外网的直连成功率和签名公证须分别验证，不能以单元测试替代。

第三方组件与对应源码材料见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。业务代码与集成测试使用 Rust/C++，部署和测量使用系统脚本；旧 Python 桥接及包装代码已移除。CI 仅在安装构建工具和下载依赖时使用 Python 辅助工具，不进入产品或运行包。
